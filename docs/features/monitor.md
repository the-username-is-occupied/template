# Eolithic Monitors — Персональный AI-аналитик

## Концепция

Monitors — модуль персонального мониторинга, который следит за выбранными источниками вместо пользователя и присылает только то, что отвечает на его конкретный вопрос.

> Ты подписан на 10 каналов — но смотреть всё времени нет. Eolithic смотрит за тебя и присылает только то, что отвечает на твой вопрос.

---

## Проблема

Пользователь подписан на YouTube-каналы и Telegram-каналы по интересующей теме. Но:

- Чтобы понять есть ли в новом видео/посте нужная информация — нужно его открыть и потратить время
- На 5–10 источников времени уже не хватает
- Результат: контент копится непрочитанным, важное теряется в потоке

Существующие решения (Junction Bot, generic AI-дайджесты) делают суммаризацию без привязки к конкретному вопросу пользователя — шум уменьшается, но не исчезает.

---

## Решение

Пользователь создаёт **монитор**: формулирует постоянный вопрос и указывает источники. Eolithic непрерывно читает эти источники и присылает только контент, релевантный именно этому вопросу — с цитатами и ссылками на оригинал.

### Механика

```
Пользователь создаёт монитор:
  └─ Вопрос/тема: "Как X реагируют на Y событие?"
  └─ Источники: [канал1, канал2, youtube3, блог4]
  └─ Формат доставки: дайджест / алерт по порогу

При появлении нового контента:
  └─ AI оценивает релевантность вопросу пользователя
  └─ Нерелевантное — отфильтровывается
  └─ Релевантное → инсайт + цитата + ссылка на источник
  └─ Накапливается до дайджеста или отправляется сразу
```

### Примеры мониторов

**Профессиональный кейс — медиааналитик:**
```
Вопрос: "Как Z-патриоты реагируют на переговоры?"
Источники: [канал1, канал2, youtube3, блог4]
Доставка: алерт сразу при появлении релевантного контента
```

**Потребительский кейс — кулинария:**
```
Вопрос: "Рецепты с лососем и азиатскими соусами"
Источники: [кулинарный канал1, youtube-шеф2, рецепты3]
Доставка: дайджест раз в неделю
```

Кулинарный кейс показывает что механика одинакова для любой ниши. Не нужно объяснять что такое grounding — достаточно одного предложения: *"ищи рецепты по ингредиентам у своих любимых авторов, получай уведомление когда выйдет что-то подходящее."* Это понимает любой пользователь за три секунды.

Паттерн универсален: кулинария, фитнес, путешествия, финансы, технологии — везде где человек подписан на нескольких авторов и хочет не потреблять всё подряд, а находить нужное.

### Формат уведомления

Уведомление даёт ценность без клика:

```
"VPN & протоколы — новое"

Outline снова доступен в большинстве регионов через нестандартные
порты. 3 источника подтверждают за последние 2 дня.

[Подробнее →]
```

```
"Кулинария — новый рецепт"

Шеф Иванов опубликовал лосось в мисо-глазури с имбирём.
Время приготовления — 25 минут.

[Смотреть рецепт →]
```

## Отличие от Knowledge Bases

| Knowledge Base | Monitor |
|---|---|
| Пользователь задаёт вопрос | Вопрос задан заранее, стоит постоянно |
| Ответ из накопленного контента | Алерт на новый контент |
| Pull — пользователь приходит сам | Push — продукт находит пользователя |
| Ретроспектива | Разведка в реальном времени |

Оба модуля дополняют друг друга: bases — для быстрых ответов по архиву, monitors — для непрерывного отслеживания новой информации.

## Целевые сегменты

**Журналисты и редакции** — мониторинг реакции конкретных сообществ на события. Telegram-каналы сейчас отслеживаются вручную, что занимает часы в день.

**Политические аналитики и консультанты** — следить за нарративами и настроениями в конкретных группах.

**Корпоративный PR/GR** — мониторинг того, как определённые сообщества реагируют на компанию, отрасль, законодательные изменения.

**Исследователи** — академики, изучающие медиа, пропаганду, дискурс.

**Продвинутые пользователи** — все кто следит за несколькими источниками по одной теме и не успевает читать всё.

## Конкурентная среда

| Продукт | Что делает | Чего не хватает |
|---|---|---|
| Junction Bot | AI-дайджест Telegram-каналов | Нет вопроса пользователя, нет YouTube |
| WorldMonitor Pro | AI-аналитик по геополитике и рынкам | Фиксированные источники, не пользовательские |
| telegram-monitor (GitHub) | Real-time мониторинг с Claude | Только для разработчиков, self-hosted |
| Telegram AI Summaries | Встроенные саммари постов | Generic, без персонализации под вопрос |

**Gap:** никто не делает связку Telegram + YouTube + мониторинг под конкретный вопрос + consumer-friendly интерфейс.

## Монетизация

Monitors — платная функция (premium / отдельная подписка).

Обоснование ценности очевидно для пользователя: продукт работает в фоне без него. Психологически это подписка на аналитика, а не на доступ к поиску — отписаться сложнее.

Ориентировочные сегменты цены:
- **Потребительский tier** — личные мониторы, ограниченное кол-во источников
- **Professional tier** — для журналистов и аналитиков, больше мониторов, экспорт, приоритетная доставка

## Технические требования

### Хранение интентов
Хранить не текст запроса, а семантику:
```
"как обойти блокировки бесплатно"
→ intent: { тема: vpn, constraint: бесплатно, регион: РФ }
```

### Фильтрация при обновлении
- Матчинг нового контента против stored intents пользователей
- Порог релевантности — отсекать слабые совпадения
- Дедупликация — одно событие из нескольких источников → один инсайт, не три уведомления

### Антиспам
- Не отправлять если похожее уже присылали
- Учитывать engagement: если пользователь не открывает уведомления — снизить частоту
- Правило по умолчанию: **одно точное уведомление в неделю лучше трёх размытых в день**

## Метрики успеха

- **Монитор активен N+ недель** без отключения — основной сигнал ценности
- **CTR уведомлений** — доля открытых алертов
- **Retention по cohort** — возвращаются ли пользователи с мониторами чаще чем без
- **Conversion free → paid** через фичу мониторов
